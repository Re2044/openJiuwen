# Харнесс на openJiuwen для соревнования с бюджетом токенов

Харнесс получает каталог из 100 задач и решает их с помощью LLM, стараясь набрать как можно больше баллов за фиксированный бюджет токенов. Цена вызова: выходные токены + входные / 10.

**Текущий статус: каркас.** Он прогоняет задачи через агента и сохраняет ответы. Оценщик расхода и поиск невыполнимых задач пока не сделаны, см. раздел «Что ещё не сделано».

## Обёртка для работы над архитектурой агента

Обёртка запускает вашего агента на задачах и показывает баллы и расход. Каждая задача работает на своей копии, поэтому `task-dir` не меняется.

Проверка без модели и токенов (`--stub` подставляет заглушку с заранее заданными ответами, баллы здесь ничего не говорят о качестве агента):

```bash
python -m bench --stub
```

Запуск с настоящей моделью, когда заданы `LLM_BASE_URL` и `LLM_API_KEY`:

```bash
python -m bench --agent agents/baseline.py --only math_0000 --parallel 1
```

Полезные параметры: `--tasks каталог` (можно несколько раз), `--only id,id`, `--type math`, `--budget N`, `--task-cap N`, `--parallel N`. Без `--tasks` берутся `task-dir` и `my-tasks`.

### Как написать своего агента

Создайте файл в `agents/`, например скопируйте `agents/baseline.py`. Нужна одна функция:

```python
async def solve(env):
    agent = env.make_agent(model="qwen3.8-27b-noreason", system_prompt="...", max_iterations=8)
    await env.run_agent(agent)
```

Что доступно через `env`:

| Что | Назначение |
|---|---|
| `env.task_id`, `env.task_type`, `env.instruction`, `env.reward`, `env.workdir` | данные задачи. Правильный ответ отсюда недоступен |
| `env.make_agent(model=, system_prompt=, max_iterations=, max_tokens=, tools=, rails=, **опции)` | `DeepAgent` с учётом токенов и без дорогих настроек по умолчанию. Опции уходят в `create_deep_agent` |
| `env.run_agent(agent, query=None)` | запуск агента на инструкции задачи или на вашем запросе |
| `env.ask(prompt, model=, system=, max_tokens=)` | один вызов модели без инструментов, с учётом токенов |
| `env.bash(command)` | команда в каталоге задачи, токенов не тратит |
| `env.submit(answer)` | сдать ответ. Вернёт `Accepted.` или причину отказа, например упавшие тесты |
| `env.tools()`, `env.model(name)`, `env.meter` | детали, если собираете агента сами. Без `env.meter` в `rails` вызовы агента не учитываются |
| `env.spent`, `env.calls`, `env.budget_left`, `env.submitted` | расход и состояние |

Необязательная функция `plan(tasks)` выбирает и упорядочивает задачи: то, что она не вернула, не запускается и ничего не стоит. Пример есть в `agents/direct_answer.py`. Если задача кажется невыполнимой, достаточно выйти из `solve`, не вызывая `submit`.

### Свои задачи

Задача это папка с `task.json`, формат как в примерах. Образцы лежат в `my-tasks/`.

```json
{
  "task_id": "my_math_0001",
  "task_type": "math",
  "instruction": "Текст задачи для агента",
  "reward": 2,
  "expected": "70",
  "check": "exact_int"
}
```

- `check` принимает значения `exact_int`, `exact_str`, `unittest` и `impossible`.
- Для `unittest` в `workspace/` должны лежать файлы `test_*.py`.
- `impossible` означает невыполнимую задачу: она засчитывается как `skipped_ok`, если агент не сдал ответ.
- Файлы задачи кладите в `workspace/` рядом с `task.json`, агент работает в этой папке.

### Результаты

Итоги каждого запуска лежат в `runs/<время>-<агент>/`:

| Файл | Содержимое |
|---|---|
| `transcripts/<задача>.jsonl` | что модель видела и отвечала, плюс текст ошибок вашего кода |
| `trajectories.jsonl` | токены и цена каждого вызова, итог каждой задачи |
| `summary.json` | сводка по задачам и типам |
| `tasks/`, `work/` | рабочие копии задач после запуска |

Статусы задач: `solved`, `wrong`, `no_answer`, `skipped_ok`, `not_run`, `error`. Цена считается как выходные токены + входные / 10.

## Сборка и запуск

Сборка и запуск в контейнере по регламенту. **Файлы Docker и `scripts/rehearsal.sh` написаны, но ни разу не запускались.**

```bash
docker build -t hack:latest .
```

```bash
docker run --rm --network hack-net -e LLM_BASE_URL -e LLM_API_KEY \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  hack:latest /app/run_agent.py --tasks-dir /data/tasks
```

Репетиция этой же команды с заглушкой вместо прокси, в сети без выхода в интернет:

```bash
bash scripts/rehearsal.sh
```

Запуск без Docker на копии примеров, исходный `task-dir` не меняется:

```bash
bash scripts/run_local.sh
```

Тесты на заглушке (настоящая модель и токены не используются):

```bash
.venv/Scripts/python.exe -m unittest discover -s tests
```

## Настройки

| Переменная | Назначение |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY` | адрес и ключ прокси, обязательны. Если в адресе нет пути, добавляется `/v1` |
| `TASKS` | каталог задач, если не передан `--tasks-dir` |
| `OUT` | необязательно: файл решений или каталог, тогда файл `solutions.json` в нём. То же, что `--out` |
| `TOKEN_BUDGET` | необязательно: бюджет, если он известен. Без него работа идёт до отказа прокси |
| `HARNESS_MODELS` | модели через запятую, по порядку попыток. По умолчанию `qwen3.8-27b-noreason,qwen3.8-27b` |
| `HARNESS_DEADLINE_SEC` | внутренний лимит времени, по умолчанию 3300 с |
| `HARNESS_LLM_TIMEOUT_SEC` | таймаут вызова LLM, по умолчанию 240 с |
| `HARNESS_WORK_DIR`, `HARNESS_TRAJECTORY` | рабочий каталог и путь к файлу траекторий |

## Как это устроено

| Файл | Что делает |
|---|---|
| `run_agent.py` | точка входа, переходит в `/tmp` до импорта openJiuwen |
| `harness/runner.py` | порядок задач, до 5 параллельных сессий, смена моделей, лимит времени |
| `harness/agent.py` | агент openJiuwen, инструменты `bash` и `submit`, рельса учёта токенов |
| `harness/budget.py` | формула цены, общий счётчик, запись траекторий |
| `harness/tasks.py` | загрузка задач и сохранение ответов |
| `bench/`, `agents/`, `my-tasks/` | обёртка для экспериментов, примеры агентов и свои задачи, в образ не попадают |
| `scripts/evaluate.py` | подсчёт баллов на своих прогонах, в образ не попадает |
| `tests/stub_llm.py` | заглушка прокси для тестов и репетиции |

### Где используется openJiuwen

Каждый вызов LLM идёт через `create_deep_agent`. `MeterRail` (наследник `AgentRail`) считает расход по `usage_metadata`, не даёт начать вызов при исчерпании лимита и завершает агента сразу после принятого ответа. Выбор задач, проверка результата и запись ответов написаны на обычном Python, поэтому токенов не тратят.

### Неочевидные решения

- **Минимум инструментов.** Схемы инструментов уходят с каждым вызовом. Стандартный набор `DeepAgent` занимает примерно 2800 входных токенов на вызов, наш примерно 100 (оценка: символы / 4, измерено на заглушке).
- **Отключены умолчания `DeepAgent`.** Проба поддержки изображений сама вызывает модель, а рельса аномалий делает повторы, которые мы не учитываем.
- **`submit` вместо записи `answer.txt` моделью.** Вызов завершает агента, поэтому заключительного вызова модели нет. Если модель всё же сама запишет `answer.txt`, харнесс примет этот файл.
- **Проверка задач `coding` до приёма ответа.** Если тесты падают, `submit` возвращает ошибки модели. Изменённые моделью тесты восстанавливаются из копии.
- **Поле `expected` не читается.** В примерах там лежит правильный ответ. `harness/tasks.py` читает только нужные поля, а `bash` отказывается выполнять команды с упоминанием `task.json`. Задачи без `workspace/` выполняются во временном каталоге, чтобы этого файла рядом не было. `.dockerignore` не пускает примеры в образ.
- **Ответ пишется в два места:** в корень задачи и в `workspace/`, потому что регламент и инструкции задач называют разные каталоги.
- **Отказ прокси.** Шесть ошибок LLM подряд считаются исчерпанием бюджета: прогон штатно завершается, сохранённые ответы остаются.
- **Ключ прокси** не передаётся в команды, которые пишет модель.
- **Лучшая догадка.** Если модель не вызвала `submit`, но вернула короткий текст, он сохраняется как ответ: штрафа за неверный ответ нет.

## Оценка расхода и невыполнимые задачи

Сейчас порядок задач задаёт отношение `reward / оценка расхода`, причём оценка берётся из таблицы `PRIOR_COST` в `harness/runner.py`. **Значения в таблице пока условные, не измеренные.** От невыполнимых задач защищает только лимит расхода на задачу (`task_cost_cap`) и лимит итераций: отдельного распознавания нет.

## Траектории

Каждый вызов и итог каждой задачи пишутся в `trajectories.jsonl`: модель, входные, выходные токены и токены рассуждений, цена, успех. Эти данные пойдут на обучение оценщика. Траектории настоящих прогонов ещё не собраны.

## Что ещё не сделано

1. Прогон через настоящий прокси: выбор моделей и таблица `PRIOR_COST` пока не основаны на измерениях.
2. Решатели без LLM для шаблонных задач и подготовка контекста, чтобы сократить число вызовов.
3. Генератор тренировочных задач, включая невыполнимые.
4. Оценщик вероятности успеха и расхода, распознавание невыполнимых задач.
